# WLD 스캘핑 조건 대시보드

**웹앱: https://jyseok0311.github.io/upbit-wld-dashboard/**

업비트 KRW-WLD 1분봉을 실시간으로 받아 기술적 지표(RSI, EMA, 볼린저밴드, VWAP, ATR, 거래량, 호가·체결 비중)를 계산하고,
셋업·트리거·확인·추세 가중 점수(0~100)로 매수·매도 타이밍을 판정해 크게 표시하는 대시보드입니다. 여기에 기능이 더 있습니다.

- **타이밍 알림**: 매수·매도 점수가 65점 이상이고 전환 트리거가 있을 때 목표가·손절가와 함께 브라우저 알림

- **수익률 매도 알림**: 보유 수량과 평균 매수가를 입력하면 수익률이 20%, 40%, 60%… 단계를 새로 넘을 때마다 브라우저 알림
- **급락 매수 알림**: 최근 N분 고점 또는 전일 종가 대비 20%(조절 가능) 이상 급락하면 브라우저 알림
- **해외 뉴스 · 속보**: 종목별(월드코인·비트코인·이더리움·솔라나) 영문 기사와 각 종목의 주요 인물·기관 기사를 GitHub Actions 로 주기 수집해 한국어로 기계 번역. 선택한 종목의 분류만 표시
- **주요 인물·기관 연관도**: 종목마다 핵심 인물·기관(WLD: OpenAI·올트먼 / BTC: 세일러·블랙록·ETF·연준 / ETH: 부테린·재단·ETF·비트마인 / SOL: 야코벤코·재단·ETF·트레저리) 헤드라인 이후 30분·60분 가격 반응, 시장 요인·테마 코인과의 상관·베타, 인물·기관별 최근 기사 수. 설정은 `public/markets.js` 에서 관리
- **4종목 한눈에**: 월드코인·비트코인·이더리움·솔라나를 같은 점수제로 판정해 카드 4장으로 나란히 표시(현재가·등락, 미니 차트, 매수·매도 점수, 켜진 트리거, 목표가·손절가). 어느 종목이든 타이밍이 뜨면 알림
- **종목 전환**: 헤더 칩(WLD · BTC · ETH · SOL)이나 관심 종목 표에서 전환. 설정은 종목별로 저장
- **WLD · OpenAI 연관도**: OpenAI·올트먼 헤드라인 이후 30분·60분 WLD 반응(BTC 대비 초과 반응), 비트코인·AI 테마 코인(TAO·NEAR·RENDER)과의 5분봉 상관·베타, 뉴스 결합도, 정규화 가격 비교 차트

> 이 도구는 지표 조건의 충족 여부를 보여줄 뿐이며 매수·매도 권유나 투자 조언이 아닙니다.
> 조건 충족이 수익을 보장하지 않으며 모든 거래 판단과 결과의 책임은 사용자에게 있습니다.

## 두 가지 실행 방식

| 방식 | 데이터 경로 |
|---|---|
| **웹 (GitHub Pages)** | 브라우저가 업비트 공개 REST(초기 캔들)와 WebSocket(실시간)을 직접 사용 |
| **로컬 미리보기** | 같은 파일을 `node server.mjs` 로 로컬에서 제공 (개발용) |

업비트 API 키나 계정 정보는 사용하지 않습니다. 보유 수량과 평균 매수가는 알림 설정에 직접 입력하며 브라우저에만 저장됩니다.
다른 종목은 주소 뒤에 `?market=KRW-BTC` 처럼 붙이면 됩니다.

## 로컬 미리보기

```powershell
node server.mjs
```

브라우저에서 http://localhost:3777 을 엽니다. 종료는 Ctrl+C.

## 화면 구성

| 구역 | 내용 |
|---|---|
| 상단 | 현재가, 전일 대비, 종합 상태(관망 / 매수 관심 / 매수 조건 다수 충족 / 매도 관심 / 매도 조건 다수 충족) |
| 차트 | 1분봉 캔들 + EMA 9/21 + 볼린저(20,2), 아래에 RSI(14). 시각은 KST |
| 지표 요약 | RSI, EMA, 볼린저, VWAP(120봉), ATR(14), 거래량 비율, 5분봉 EMA 20/50, 스프레드, 24h 고저 |
| 호가 · 체결 | 상위 10호가 잔량과 매수/매도 잔량 비율, 최근 200건 체결의 매수·매도 비중 |
| 타이밍 배너 | 관망 / 매수·매도 준비 / 매수·매도 타이밍을 크게 표시. 매수·매도 점수 게이지, 점수 구성(셋업·트리거·확인·추세), 진입가·목표가·손절가·손익비 |
| 매수 점수 · 매도 점수 | 셋업·트리거·확인·추세 항목별 배점과 현재값 (아래 "타이밍 판정" 참고) |
| 내 포지션 · 알림 설정 | 수량·평단 입력, 수익률·평가손익, 다음 매도 알림가, 고점·전일 대비 낙폭, 알림 켜기/테스트 |
| 알림 기록 | 발송된 매도·매수 알림 목록 (브라우저에 저장) |
| 상태 변화 로그 | 종합 상태가 바뀔 때마다 시각·가격·충족 개수 기록 |

종합 상태 규칙은 아래 "매수·매도 타이밍 판정" 절을 참고하세요.

## 파일 구성

```
public/index.html   화면 마크업·스타일
public/app.js       데이터 수신(REST 초기화 + WebSocket) · 렌더링
public/engine.js    지표 계산 · 조건 판정 (순수 함수)
public/news.js      뉴스 탭 (news.json 표시) · 탭 전환
public/relate.js    WLD·OpenAI 연관도 분석 탭 (뉴스 반응 · 상관 · 베타)
public/sw.js        서비스 워커 (알림 클릭 처리) · manifest.json PWA 설치 정보
scripts/fetch-news.mjs        구글 뉴스 RSS 수집 + 한국어 번역 → public/news.json
server.mjs          로컬 미리보기용 정적 파일 서버
.github/workflows/pages.yml   GitHub Pages 자동 배포
```

## 매수·매도 타이밍 판정 (점수제)

단순히 조건 개수를 세던 방식 대신, 매수·매도 각각 0~100점을 매겨 상단 배너와 헤더에 크게 표시합니다.

| 구성 | 배점 | 내용 |
|---|---|---|
| 셋업 (어디에 있나) | 35 | RSI 과매도/과매수(단계별), 볼린저 %B, VWAP 대비 위치·괴리(ATR 배수) |
| 트리거 (지금 도는가) | 40 | RSI 과매도·과매수권에서 반전, 볼린저 밴드 이탈 후 복귀, 반전 캔들(망치형·유성형·장악형), EMA9/21 교차, EMA9·VWAP 회복/이탈 |
| 확인 (수급이 따르나) | 25 | 호가 잔량 우위, 최근 체결 방향 비중(30건 이상 쌓인 뒤), 반전 봉 거래량(완료 봉 20개 평균 대비) |
| 추세 배수 | ×0.7~1.0 | 5분봉 EMA20/50 추세와 같은 방향이면 1.0, 반대면 0.85, 강한 반대 추세면 0.7 |
| 감점 | −8씩 | 스프레드 0.25% 초과, 1분봉 ATR 0.08% 미만(수수료 대비 이득이 작음) |

- **타이밍**: 점수 65 이상 + 트리거 1개 이상 + 반대 점수보다 20점 이상 높을 때. 배너가 커지며 빛나고, 차트에 화살표 마커와 목표가·손절가 선이 그려지고, 타이밍 알림(방향별 5분 간격)이 발송됩니다.
- **준비**: 점수 40 이상. 셋업은 갖춰졌지만 전환 트리거가 아직 없는 상태입니다.
- **관망**: 그 외.
- 강한 신호는 최소 3분 동안 표시를 유지해 깜빡임을 막고, 반대 신호가 뜨거나 점수가 40 아래로 내려가면 해제됩니다.
- 목표가는 볼린저 중심선·VWAP(0.5 ATR 이상 떨어져 있을 때) 또는 1.5 ATR, 2차 목표는 반대편 밴드 또는 2.5 ATR, 손절은 최근 10봉 저점(고점) ± 0.3 ATR 입니다. 손익비도 함께 표시합니다.
- 진행 중인 1분봉의 거래량은 경과 시간으로 환산해 완료 봉과 비교합니다(20초 이상 지난 뒤부터).

배점·기준값은 `public/engine.js`의 `computeAll` 안 `buy`, `sell` 배열과 `STRONG`, `WATCH`, `GAP` 상수에서 바꿀 수 있습니다.

## 알아둘 점

- 업비트는 브라우저(Origin 헤더)에서 오는 REST 요청과 WebSocket 접속을 IP 단위로 제한합니다(실측 약 10초당 1회).
  이 앱은 모든 REST 호출을 한 큐에 넣어 11초 간격으로 차례로 보냅니다: 현재 종목 1분봉·5분봉 → 관심 종목 1분봉 3개 → 비교 종목 5분봉 6개.
  접속 후 약 2분이면 모든 데이터가 채워지며, 이후는 WebSocket으로만 갱신합니다.
  받아 둔 캔들은 브라우저(localStorage)에 30초마다 저장되므로, 새로 고침하거나 종목을 바꿀 때는 캐시로 즉시 표시하고
  캐시가 직전 봉까지 있으면 REST 초기 요청을 건너뜁니다(두 번째 접속부터는 1~2초 안에 판정 시작).
  실측으로 WebSocket 접속과 REST 요청이 같은 약 10초 제한을 공유하므로, 접속 직후 첫 REST 는 11초 뒤에 보냅니다.
  짧은 시간에 여러 번 새로 고침하거나 탭을 여러 개 열면 제한에 걸릴 수 있으며, 이때 상단에 자동 재시도 안내가 표시되고
  과거 캔들을 못 받아도 실시간 1분봉이 60개 쌓이면 지표가 계산됩니다.
- 알림은 페이지가 열려 있을 때(백그라운드 탭 포함) 브라우저 알림으로 도착합니다. 브라우저를 완전히 닫은 상태의 푸시는 별도 서버가 필요해 지원하지 않습니다.
  휴대폰에서는 브라우저 메뉴의 "홈 화면에 추가"로 설치(PWA)해 두면 앱처럼 띄워 둘 수 있습니다.
- 이 앱은 업비트 API 키를 요구하지 않으며 주문·잔고 같은 계정 기능이 없습니다. 공개 시세만 사용합니다.
