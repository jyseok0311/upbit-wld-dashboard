# WLD 스캘핑 조건 대시보드

업비트 KRW-WLD 1분봉을 실시간으로 받아 기술적 지표(RSI, EMA, 볼린저밴드, VWAP, ATR, 거래량, 호가·체결 비중)를 계산하고,
미리 정한 매수·매도 조건 7개씩의 충족 여부를 표시하는 대시보드입니다.

> 이 도구는 지표 조건의 충족 여부를 보여줄 뿐이며 매수·매도 권유나 투자 조언이 아닙니다.
> 조건 충족이 수익을 보장하지 않으며 모든 거래 판단과 결과의 책임은 사용자에게 있습니다.

## 두 가지 실행 방식

| 방식 | 데이터 경로 | 잔고 패널 |
|---|---|---|
| **웹 (GitHub Pages)** | 브라우저가 업비트 공개 REST(초기 캔들)와 WebSocket(실시간)을 직접 사용 | 표시 안 함 |
| **로컬 서버** | 시세는 웹과 동일, 잔고만 서버가 업비트 공식 CLI(`upbit`)로 조회 | API 키(자산 조회 권한) 등록 시 표시 |

다른 종목은 주소 뒤에 `?market=KRW-BTC` 처럼 붙이면 됩니다.

## 로컬 실행

```powershell
npm install -g @upbit-official/upbit-cli   # 최초 1회
upbit.cmd config set                        # 잔고를 보려면 API 키 등록 (선택)
node server.mjs
```

브라우저에서 http://localhost:3777 을 엽니다. 종료는 Ctrl+C.

## 화면 구성

| 구역 | 내용 |
|---|---|
| 상단 | 현재가, 전일 대비, 종합 상태(관망 / 매수 관심 / 매수 조건 다수 충족 / 매도 관심 / 매도 조건 다수 충족) |
| 차트 | 1분봉 캔들 + EMA 9/21 + 볼린저(20,2), 아래에 RSI(14). 시각은 KST |
| 지표 요약 | RSI, EMA, 볼린저, VWAP(120봉), ATR(14), 거래량 비율, 5분봉 EMA 20/50, 스프레드, 24h 고저 |
| 호가 · 체결 | 상위 10호가 잔량과 매수/매도 잔량 비율, 최근 200건 체결의 매수·매도 비중 |
| 매수 관심 조건 (7) | RSI 32 이하, 볼린저 하단 이하, 거래량 1.8배, 매수잔량 우위 1.2배, 체결 매수 55%, 5분봉 상승 배열, EMA 골든크로스 |
| 매도 · 이탈 조건 (7) | RSI 68 이상, 볼린저 상단 이상, EMA 데드크로스, 매도잔량 우위 1.2배, 체결 매도 55%, 5분봉 하락 배열, VWAP 아래 이탈 |
| 보유 현황 | (로컬 서버) 보유 수량, 평균 매수가, 평가 금액·손익, 보유 원화 |
| 상태 변화 로그 | 종합 상태가 바뀔 때마다 시각·가격·충족 개수 기록 |

종합 상태 규칙: 한쪽 조건이 3개 충족되면 "관심", 4개 이상이면 "조건 다수 충족". 양쪽 개수가 같으면 관망.

## 파일 구성

```
public/index.html   화면 마크업·스타일
public/app.js       데이터 수신(REST 초기화 + WebSocket) · 렌더링
public/engine.js    지표 계산 · 조건 판정 (순수 함수)
server.mjs          로컬 서버: 정적 파일 + /api/holdings (upbit CLI)
.github/workflows/pages.yml   GitHub Pages 자동 배포
```

조건 기준값(32, 68, 1.8, 1.2, 0.55 등)은 `public/engine.js`의 `computeAll` 안 `buy`, `sell` 배열에서 바꿀 수 있습니다.

## 알아둘 점

- 브라우저에서 보내는 업비트 REST 요청은 분당 약 6회로 제한되어 초기 캔들 3회만 REST로 받고 이후는 WebSocket을 씁니다.
  짧은 시간에 여러 번 새로 고침하면 429 응답이 올 수 있으며, 이때 화면 상단에 자동 재시도 안내가 표시됩니다.
- API 키는 이 저장소에 포함되지 않습니다. 로컬 서버는 `upbit config set`으로 사용자 홈 폴더에 저장된 키를 읽습니다.
